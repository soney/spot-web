{%- comment -%} Resolves the light/dark theme and stamps it on as data-theme, which is what the dark-mode blocks in assets/css/site.css and assets/css/cv.css key off. Also wires up the navbar toggle from _includes/theme_toggle.html, if the page has one. Inline and blocking, in before the stylesheets, on purpose. The attribute has to exist before the first pixel is painted or a reader whose stored choice differs from their OS preference sees the wrong theme flash. That rules out a deferred external file, and an external blocking one would cost a round trip for ~40 lines. This script is an override, not the mechanism. The stylesheets carry both palettes in light-dark() pairs and follow the OS on their own, so with JavaScript off -- when nothing below ever runs and the attribute is never set -- a reader on a dark OS still gets the dark site. All this adds is the ability to disagree with the OS. The toggle itself hides in that case (the stylesheets key its display off `:root[data-theme]`), so there is no control that does nothing when clicked. Storing nothing until the reader clicks is what lets `stored()` double as "has the reader chosen?", which is how the OS-preference listener knows whether it is still allowed to follow along -- and it is why an untouched browser gets the pure-CSS path above rather than a value this script guessed. {%- endcomment -%}
